# 10. 로비 채팅

## 목적

"지금 접속한 사람끼리 바로 말을 건다." 사이트를 보는 사람 모두가 하나의 대화방을 공유한다.
읽기에는 계정이 필요 없고, 쓰기와 삭제는 RPCN 계정으로 로그인해야 한다.

## 화면 (FE `src/chat/`)

- 레이아웃 안에 한 번만 마운트되고 탭을 옮겨 다녀도 유지된다. 따라서 스트림 연결은 방문하는 동안 하나다.
- 폭 1350px 이상: 본문 오른쪽에 항상 열린 세 번째 열로 붙는다.
- 그보다 좁으면: 왼쪽 아래 런처 버튼으로 접힌다. 런처에는 안 읽은 메시지 수가 표시되고, 휴대폰에서는 전체 화면 시트로 열린다.

## 도메인 규칙 (`chat/domain.py`, `chat/service.py`, `chat/models.py`)

| 규칙 | 내용 |
|------|------|
| 보이는 범위 | **전날 06:00 KST**부터(`history_start`). 플레이 하루는 06:00에 시작하며 통계·예약과 같은 경계다. 06:00 직후에 대화가 끊겨 보이지 않도록 전날까지 보여 준다 |
| 스냅샷 상한 | 위 범위 안에서 최신 **500개**(`chat.db.MAX_LISTED_MESSAGES`) |
| 본문 | 앞뒤 공백을 제거한 뒤 1~200자. 공백만 있는 줄은 빈 메시지로 취급해 거부한다(422) |
| 도배 방지 | 계정당 **1초에 1개**. 어기면 429. 마지막 작성 시각은 메모리에 있어서 재시작하면 잊는다 |
| 삭제 권한 | 본인 메시지, 또는 관리자는 모든 메시지. 남의 메시지는 403, 없는 메시지는 404 |
| 관리자 표시 | 작성 시점 토큰의 `admin` 클레임을 메시지에 함께 저장한다(`author_admin`) |

## 저장 (`chat/adapters/postgresql.py`)

- PostgreSQL `chat_messages` 테이블. 배포나 재시작 뒤에도 최근 채팅과 삭제 상태가 그대로 남는다.
- id는 `BIGINT IDENTITY`라서 재시작해도 이어지고, 같은 값이 다시 나오지 않는다.
- 삭제는 행 자체를 지우는 하드 삭제다.
- 보이는 범위보다 오래된 행은 지우지 않고 남겨 둔다. 읽는 곳이 없고, 정리 작업은 아직 두지 않았다.
- `created_at`은 DB의 `now()`가 아니라 서비스 시계로 기록한다. 보이는 범위를 계산하는 것도 같은 시계다.
- `MemoryChatRepository`는 단위 테스트용으로만 남아 있다.

## 실시간 전달

`GET /chat/stream`은 Server-Sent Events(`fastapi.sse.EventSourceResponse`)다.

| 이벤트 | 데이터 | 시점 |
|--------|--------|------|
| `snapshot` | 메시지 배열(오래된 순) | 연결마다 맨 처음 한 번 |
| `message` | 메시지 하나 | 누군가 글을 쓸 때 |
| `delete` | `{ "id": … }` | 메시지가 삭제될 때 |

- 서버는 15초마다 `: ping`을 보낸다. CloudFront의 30초 오리진 타임아웃 안쪽이다.
- 재연결하면 `Last-Event-ID`로 이어 받지 않고 새 스냅샷을 받는다. 끊긴 동안 일어난 삭제는 목록 전체를 새로 받아야만 반영되기 때문이다. 클라이언트는 스냅샷이 올 때마다 목록을 통째로 바꾸고, 스냅샷과 이벤트에 겹친 메시지는 id로 중복을 제거한다.
- 이벤트 버스(`ChatEventBus`)는 프로세스 메모리에 있다(`adapters/memory_bus.py`). 스트림마다 100개짜리 큐가 있고, 큐가 가득 찬 스트림은 끊는다. 끊긴 클라이언트는 다시 연결해 새 스냅샷을 받는다. 프로세스가 둘이 되면 Redis pub/sub 같은 버스로 바꿔야 한다.

## API

| 메서드 | 경로 | 인증 | 응답 |
|--------|------|------|------|
| GET | `/chat/stream` | 없음 | SSE (위 표) |
| POST | `/chat/messages` | Bearer | 201, 작성된 메시지 |
| DELETE | `/chat/messages/{id}` | Bearer | 204 |

메시지 형태: `id`, `author_username`, `author_online_name`, `body`, `created_at`, `author_admin`.
