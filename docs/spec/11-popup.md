# 11. 사이트 팝업

## 목적

관리자가 공지나 이벤트 안내를 사이트에서 바로 띄운다. 패치노트와 달리 코드 배포 없이 관리 페이지에서 쓰고 이미지를 올린다.
로그인 여부와 무관하게 모든 방문자가 본다.

## 화면 (FE `src/popup/`, `src/admin/PopupAdmin.tsx`)

- 페이지를 열 때 뜬다. 패치노트가 열려 있으면 그것이 닫힌 뒤에 뜬다.
- 활성 팝업이 여럿이면 최신순으로 하나씩 뜬다.
- 조회가 실패하면 아무것도 띄우지 않는다.
- 관리자는 `/admin`의 팝업 섹션에서 만들고, 고치고, 지운다. 비밀번호는 묻지 않는다.

## 도메인 규칙 (`popup/domain.py`, `popup/dependencies.py`)

| 규칙 | 내용 |
|------|------|
| 제목 | 앞뒤 공백을 제거한 뒤 1~100자 |
| 내용 | 앞뒤 공백을 제거한 뒤 0~2000자. 이미지만 띄우는 팝업은 비워 둘 수 있다. 일반 텍스트이며 줄바꿈만 유지한다 |
| 이미지 | 팝업당 1장, 5MB까지. PNG, JPEG, WebP, GIF |
| 이미지 형식 판정 | 파일 이름이나 클라이언트의 Content-Type이 아니라 **파일 시그니처**로 판정하고, 판정한 형식을 저장한다. SVG는 스크립트를 담을 수 있어 받지 않는다 |
| 닫기 버튼 | 팝업마다 `allow_dismiss_day`(하루 동안 보지 않기)와 `allow_dismiss_forever`(다시 보지 않기)를 따로 켠다. 둘 다 끄면 X로만 닫히고 다음 접속 때 다시 뜬다 |
| 활성 | `active`가 참인 팝업만 방문자에게 보인다. 노출 기간은 없고 관리자가 끈다 |
| 권한 | 관리자 API는 토큰의 `admin` 클레임으로 판단한다. 이 서비스의 테이블만 건드리므로 RPCN 비밀번호를 다시 묻지 않는다 |

## 닫기 기록

서버는 누가 무엇을 닫았는지 기록하지 않는다. 비로그인 방문자에게는 기록을 걸 계정이 없다.
브라우저 localStorage의 `ttt2-popups-dismissed`에 팝업 id별로 저장한다.

- **다시 보지 않기**: 영구.
- **하루 동안 보지 않기**: 누른 시점부터 24시간. 플레이 하루(06:00)와 무관하다.
- X, 배경 클릭, Esc: 기록하지 않아서 다음 페이지 로드 때 다시 뜬다. 패치노트와 같다.
- 다른 브라우저나 기기에서는 다시 뜬다.
- 팝업을 수정해도 이미 닫은 사람에게 다시 뜨지 않는다. 다시 알리려면 새 팝업을 만든다.

## 저장 (`popup/adapters/postgresql.py`)

- PostgreSQL `popups` 테이블. 이미지는 `image` 컬럼(`bytea`)에 함께 저장해서 팝업을 지우면 이미지도 지워진다.
- `image`는 지연 로드 컬럼이다. 목록 조회는 이미지 바이트를 읽지 않는다.
- 삭제는 행 자체를 지우는 하드 삭제다.

## 캐시

| 대상 | 내용 |
|------|------|
| `popups:active` | `cache_ttl_popups`(60초). 생성·수정·삭제 시 바로 지운다 |
| 이미지 | 서버 캐시 없음. `Cache-Control: public, max-age=31536000, immutable`로 브라우저가 보관한다. 경로의 `?v=`가 내용 해시라서 이미지를 바꾸면 주소가 바뀐다. `/api`는 CloudFront가 캐시하지 않는다 |

## API

| 메서드와 경로 | 권한 | 내용 |
|------|------|------|
| `GET /popups/active` | 공개 | 활성 팝업 목록, 최신순 |
| `GET /popups/{id}/image` | 공개 | 이미지 바이트. 없으면 404 |
| `GET /admin/popups` | 관리자 | 비활성을 포함한 전체 목록, 최신순 |
| `POST /admin/popups` | 관리자 | 생성. 201 |
| `PUT /admin/popups/{id}` | 관리자 | 수정. `image`를 보내지 않으면 저장된 이미지를 유지하고, `remove_image`가 참이면 지운다 |
| `DELETE /admin/popups/{id}` | 관리자 | 삭제. 204 |

`POST`와 `PUT`은 `multipart/form-data`다. 필드는 `title`, `body`, `allow_dismiss_forever`, `allow_dismiss_day`, `active`, `image`(파일)이고, `PUT`에는 `remove_image`가 더 있다.

`image_path`는 API 루트 기준 상대 경로이며, 이미지가 없으면 null이다.

| 상태 | 뜻 |
|------|-----|
| 400 | 5MB를 넘거나 허용하지 않는 이미지 |
| 401 | 토큰 없음 또는 만료 |
| 403 | 관리자 아님 |
| 404 | 없는 팝업, 또는 이미지가 없는 팝업의 이미지 |
| 422 | 제목·내용 규칙 위반 |

업로드 크기는 FE의 nginx(`client_max_body_size 6m`, `/api/`)가 먼저 막는다. 이미지 5MB에 폼 필드 몫을 더한 값이다.
